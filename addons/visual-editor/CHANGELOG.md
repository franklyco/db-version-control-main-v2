# Changelog

## Unreleased

- Landed R5.6 (Nested-record ancestry hardening, defensive). The Brand Control Center drawer's per-record Availability gate now applies the same "every intermediate must be an ACF Group field" ancestry check to every unlocked family — R5.1 text, R5.2 choice/link/wysiwyg/true_false, R5.2+color_picker, R5.3 image, and R5.4 relationship/post_object — not only R5.4 reference collections as before. Nothing visible changes on the live site today: all 182 R5.1 text records and the other 215+ nested unlocked records happen to have group-only chains, so they stay Available. The value of the slice is future-proofing: if the maintainer's curation ever adds a record nested inside a Repeater or Flexible-Content field, that record now stays Unsupported at the drawer surface — the Open button never appears — instead of surfacing an Open button whose save would silently land on the wrong meta key. The gate helper was also renamed from `hasGroupOnlyAncestry` to `parentChainIsGroupOnly` to reflect the family-agnostic role. Zero new REST routes, zero new mutation authority, zero new resolvers, zero new mutation contracts. Repeater/flexible-content nested support (the actual capability, as opposed to the defensive short) is deferred to a dedicated R5.7 slice that will ship the `writeRepeaterSubfieldValue` primitive + row-index tracking + drawer UI for per-row records.
- Landed nested reference-collection support — the Brand Control Center drawer's descriptor factory now handles group-nested relationship + post_object fields by walking the ACF parent chain and emitting `source.group_write_path` (the Media Manager RK-013 pattern) so saves route THROUGH the parent group's own `update_value`. Top-level reference records are byte-identical to before. On the Vertical side, curated reference records with a `>` in their field path (nested) now trigger a lightweight ACF introspection at drawer-list time: if every intermediate parent is an ACF Group field, the record flips Available; if any intermediate is a repeater or flexible-content field, it stays Unsupported (a repeater-subfield save needs a different write path than this slice ships). Whether the one specific curated `settings_nav_menus>menus>menu_posts` record unlocks on your live site depends on how `menus` is configured in ACF: group → unlocks; repeater → stays unsupported (correctly). Zero new REST routes, zero new mutation authority, zero new resolvers, zero new mutation contracts. The two-part kill switch still gates the whole feature. **Live-site coverage now 397–398 of 400 curated Vertical rows (99.25–99.5%)** depending on that one field's ACF structure. This closes the R5 arc for every family with an existing resolver + panel controller and every intermediate-is-group nesting pattern. The last known-safe unlock frontier — records nested inside a repeater or flexible-content field — remains a genuinely-separate future slice that needs new primitives.
