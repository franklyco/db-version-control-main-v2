# Brand Control Center — Release Notes & Rollback (R3-D + R5.7 + R5.later-a)

Ship-readiness summary for the Registry-Backed Brand Control Center (R3-A registry foundation → R3-B Shared Globals provider → R3-C-1 backend + REST routes → R3-C-2 drawer UI → R3-D hardening) plus the R5.7 inline-tree slice (Option C-1 shape: R5.7-a backend + row-signature integrity → R5.7-b drawer tree UI → R5.7-c release notes + real-browser QA plan). Companion to the per-phase release docs in this folder.

## What shipped

**R3-A — provider-agnostic control registry (foundation).** Discovery-only `ControlProvider` interface + `ControlRecord` value object with whitelisted normalization and a safe list projection that excludes the opaque per-record `source` bag; `ControlRegistry` collects providers, validates/normalizes/de-dupes records, and re-applies per-user visibility on every list call. Duplicate providers, duplicate local ids, and malformed records are rejected observably via `dbvc_visual_editor_control_registry_invalid`. `getVisibleRecord(publicId)` is the internal bridge R3-C-1's open route uses. No REST, no UI, no `Addon::register` wiring yet.

**R3-B — Shared Globals compatibility provider (headless).** `Registry\Providers\SharedGlobalsControlProvider` adapts the existing configured Shared Globals field list onto the registry as a discovery-only surface: one `ControlRecord` per configured `relationship`/`post_object` field with `category=globals`, `ownerType=option`, `ownerSubtype=acf_options`, an opaque `source={field_name, field_key}` hint, and a `visibleTo` closure that reproduces `SharedGlobalFieldsController::canManageSharedGlobalOptions` verbatim. Two-part kill switch introduced (D-063): `OPTION_CONTROL_CENTER_ENABLED` + master switch, both default off. `Bootstrap\Addon` instantiates `ControlRegistry` unconditionally and exposes `getControlRegistry()` for downstream slices. `SharedGlobalFieldsController` is untouched — parallel discovery, not a replacement.

**R3-C-1 — Brand Control Center backend + descriptor factory extraction.** Extracted `SharedGlobalFieldsController::buildDescriptor` and its private helpers into a stateless `Registry\Providers\SharedGlobalsDescriptorFactory` (byte-identical to the pre-extraction inline emit; associative-array key ordering preserved). Widened the R3-A `ControlProvider` interface with `buildDescriptor(ControlRecord $record, string $sessionId, array $pageContext): ?EditableDescriptor` and implemented it on `SharedGlobalsControlProvider`. New `ControlRegistry::buildDescriptorForRecord()` keeps the private providers map encapsulated. Two new session-scoped REST controllers wired into `Rest\Routes` under the kill switch:
- `ControlCenterListController` — `GET /dbvc/v1/visual-editor/session/{session_id}/control-center/controls` returns the safe list projection.
- `ControlCenterOpenController` — `POST /dbvc/v1/visual-editor/session/{session_id}/control-center/open` resolves a `publicId` → provider `buildDescriptor` → per-descriptor capability recheck → session attach → returns `{descriptors, descriptorHydrations}` in the same shape the existing frontend panel already consumes.

**R3-C-2 — drawer UI translation.** `assets/js/brand-control-center-app.js` (~900 lines) translates the accepted mockup at `docs/ui-mockups/dbvc-visual-editor/r3-brand-control-center/` into production. Mirrors `media-manager-app.js`'s lifecycle. Scoped `assets/css/control-center.css` with a single new `--dbvc-ve-z-drawer: 120015` `:root` token. `AssetLoader` gained a kill-switch-gated enqueue branch + a `controlCenter: {enabled, restBase}` bootstrap block + ~40 drawer i18n strings. `overlay-app.js` gained a `sliders` dock toolbar entry after `shared-globals` (D-063 keeps the popover slot untouched), a `control-center` click branch that dispatches `dbvc:visual-editor:control-center:toggle`, and a `bindControlCenterBridge()` document listener for `dbvc:visual-editor:absorb-descriptor` that reuses the existing internal `mergeSharedGlobalInventory` + `openToolbarDescriptorPanel` helpers — the same helpers the Shared Globals popover already uses, so the panel behaves identically regardless of entry point. Filtering across tab / status / priority / field-family / search is client-side; the wire stays stateless.

**R3-D — production hardening (this doc).** New `VisualEditorControlCenterHardeningTest` locks down: the two-part kill switch's registration guarantee (both REST routes registered only when both switches are on; absent when either is off; mid-session flip makes them unreachable), and the Bricks Builder isolation (drawer stylesheet + script do NOT enqueue inside a Bricks Builder request — verified against `FrontendRuntimeGuard`'s isBuilderRequest via `$_GET['bricks']`).

## Feature gates & isolation (verified)

- **Two flags, default-off.** The Brand Control Center is active only when the Visual Editor master flag **and** the Control Center flag are both on (`is_control_center_enabled()` = `is_enabled()` AND the feature flag). Turning off either closes the entire surface (routes, drawer JS/CSS, and toolbar entry all disappear).
- **Capability + authentication.** Every REST route's `permission_callback` (`canAccess`) requires a logged-in user with the base capability (`edit_others_posts`, filterable). Each open call additionally checks `EditModeState::isRestRequestAuthorized()` (edit-mode cookie present and set) and re-checks `CapabilityManager::canEditDescriptor` on the freshly-minted descriptor before attaching it to the session.
- **Per-user visibility.** Every list call re-applies the record's `visibleTo` closure against the current user — the same closure that fronts `canManageSharedGlobalOptions` for the popover. Subscribers see nothing; administrators see every configured Shared Globals record.
- **Bricks Builder exclusion.** `AssetLoader::enqueue` short-circuits via `EditModeState::shouldLoadFrontendAssets()` → `isActive()` → `runtime_guard->shouldRunFrontend()` before reaching the drawer branch. Verified by `VisualEditorControlCenterHardeningTest::test_drawer_assets_do_not_enqueue_inside_bricks_builder`.
- **No new write authority.** The drawer opens rows into the existing main editor panel via the existing `mergeSharedGlobalInventory` + `openToolbarDescriptorPanel` bridge — same panel, same save path, same `MutationService` pipeline, same journal + audit + cache invalidation as the Shared Globals popover.
- **Parallel popover coexistence (D-063).** `SharedGlobalFieldsController::handle()`'s public response is byte-identical to its pre-R3-C-1 shape. The Shared Globals popover keeps working exactly as it did before R3; users who prefer the popover can continue using it while the drawer opt-in stays off.

## Side effects & boundaries

- **Writes:** none from R3 itself. The drawer opens a control into the existing panel; whatever the user saves in the panel routes through the existing `MutationService` pipeline (validation → sanitize → resolver save → change journal → audit event → cache invalidation).
- **Never:** creates new REST endpoints for writing; adds new write authority; caches descriptors client-side beyond the panel's existing hydration cache; sends any raw target (owner id, field key, selector, path, descriptor, token) into the DOM. Rows carry only `data-public-id` — enforced structurally in `brand-control-center-app.js`'s row builder and asserted by `visual-editor-brand-control-center-state.test.cjs`.
- **Storage:** none. The registry is in-process; provider registrations live for the request. No custom table, no persistent option beyond `OPTION_CONTROL_CENTER_ENABLED` (a single '0'/'1' setting).
- **Frontend enqueue footprint (when both switches on):** one CSS file (~600 lines) + one JS module (~900 lines) + one added toolbar button. All Bricks-Builder-isolated. Zero editor / media / TinyMCE / wp-color-picker enqueue that the Visual Editor overlay didn't already load.

## Rollback runbook

Rollback is feature-level and non-destructive — no data migration is involved.

1. **Disable the Control Center flag** (`dbvc_visual_editor_control_center_enabled` → off, via Settings → Visual Editor → *Enable Brand Control Center*). Effect: `is_control_center_enabled()` returns false → `Rest\Routes::registerRoutes` no longer registers the list or open route (verified by `test_routes_are_absent_when_feature_switch_is_off`); `AssetLoader::enqueue` skips the drawer stylesheet + script (verified by `test_drawer_assets_do_not_enqueue_when_feature_switch_is_off`); `overlay-app.js`'s `isControlCenterEnabled()` returns false so the toolbar entry disappears on the next page load and the `bindControlCenterBridge()` document listener is not bound. This is the primary, instant kill switch. The rest of the Visual Editor overlay and the Shared Globals popover are unaffected.
2. **Disable the Visual Editor master flag** (`dbvc_addon_visual_editor_enabled` → off) to remove the Brand Control Center and the entire Visual Editor overlay together. `is_control_center_enabled()` requires BOTH switches, so master-off is a superset of feature-off (verified by `test_routes_are_absent_when_master_switch_is_off`).
3. **The Shared Globals popover keeps working under both rollback modes.** `SharedGlobalFieldsController::handle()` is the popover's route — it was refactored in R3-C-1 to delegate to a shared factory but its public response is byte-identical. The popover's toolbar entry is a separate slot (`shared-globals`) that R3 did not touch. Rolling R3 back does not affect the popover in any way.
4. **No content is orphaned.** R3 writes nothing. Any values a user saved via a control opened from the drawer are ordinary WordPress/ACF content that was written by the existing panel's save path — the same code the popover uses. Rolling R3 back does not change any persisted value.
5. **Code revert.** Reverting the R3 add-on code removes the registry, providers, REST controllers, drawer JS/CSS, and the toolbar entry cleanly. There is **no R3-specific schema migration** to undo — `OPTION_CONTROL_CENTER_ENABLED` can be left in place or deleted, and the popover route + descriptor factory extraction can be reverted as a unit (`SharedGlobalFieldsController` regains its inline `buildDescriptor` + private helpers) without any behavioral change to the popover's public response.
6. **Pre-flip verification** (recommended before flipping the switch off in production):
   - `curl` the popover route (GET `/dbvc/v1/visual-editor/session/{id}/shared-global-fields`) with a valid nonce; capture the response.
   - Flip the Control Center switch off.
   - `curl` the popover route again; the response must be byte-identical.
   - `curl` the two Control Center routes; both must return 404.
   - Visit a frontend page in Visual Editor mode; the toolbar's `sliders` slot must be absent, the `layers` (Shared Globals) slot must still work.

# R5.7 — Inline Tree (repeater subfield support) — Release Notes & Rollback

Ship-readiness summary for R5.7-a (DBVC backend + Vertical unroll) +
R5.7-b (drawer tree UI) + R5.7-c (this doc + QA plan). Layered on the
R3 foundation above; every R3 gate still applies.

## What shipped (R5.7)

**R5.7-a — DBVC backend + Vertical unroll (2026-09-01).** The Brand Control Center backend gains a repeater-subfield editing path. New public static `SharedGlobalsControlProvider::buildRepeaterRowSignature($row)` returns a deterministic sha1 hash of a row's data (recursive `ksort`, strips ACF `acf_row_*` transient keys, non-scalar leaves in nested arrays coerce to null for stable hashing). New public method `SharedGlobalsDescriptorFactory::buildRepeaterSubfieldDescriptor($session_id, $page_context, $parent_repeater_field, $subfield_field, $row_index, $expected_row_signature, $row_key = '')` mints an `EditableDescriptor` for a leaf subfield inside a specific repeater row — source shape branches on family: `acf_collection_field` + `render.context='query_collection'` for reference leaves (matches `AcfReferenceCollectionResolver::supports`), `acf_repeater_subfield` + `render.context='field'` for scalar leaves (matches `AbstractAcfResolver::isRepeaterSubfieldSource`); `parent_field_selector` uses the repeater's KEY so ACF key-based lookup handles group-nested repeaters (`settings_nav_menus > menus`); source embeds `row_index` + `expected_row_signature` + all normal per-family metadata. Supports 10 families (text/textarea/url/email/number, select/checkbox/radio/button_group, link, wysiwyg, image, color_picker, true_false, relationship, post_object). New protected `AbstractAcfResolver::verifyExpectedRowSignature($descriptor, $row)` compares descriptor signature against a freshly-computed one and returns `{ok:false, code:'concurrent_reorder_detected', message:...}` on mismatch — hook called inside `writeRepeaterSubfieldValue` between validation and post-meta fallback; legacy descriptors without a signature skip the check (backwards-compat). **Vertical (both checkouts, byte-identical via `cp` + `diff -q`)**: `parseParentChain()` shared walker replaces the R5.6 inline walk; new `parentChainImmediateRepeaterInfo()` detects the "leaf's immediate parent is a repeater + every ancestor above is a group" shape R5.7-a targets. `getControls()` runs `maybeExpandRepeaterRecord()` after `mapRecord` — when the record is a repeater-nested candidate + rows lift successfully, emits (1) a synthetic parent record (`meta.role='repeater_parent'`, `meta.childCount=N`, `status='unsupported'`; deduped across sibling subfield curation entries) + (2) N leaf records with `source.role='repeater_leaf'`, `source.row_index`, `source.expected_row_signature`, `parentPublicId` linking to parent. `buildDescriptor()` routes leaves through `buildRepeaterLeafDescriptor()` which lifts parent + subfield field objects and delegates to DBVC's factory. `buildValueSummary()` routes leaves through `extractRepeaterLeafValue()` which lifts row + subfield value and delegates to family static builders.

**R5.7-b — Drawer tree UI (2026-09-02).** The R5.7-a flat interim state folds into the intended compact tree render. `ControlRecord` gains public `$parentPublicId` property (same-provider-prefix validation; cross-provider values silently drop to `''` — record still surfaces flat). New private static `sanitizeMetaKey()` case-preserving alternative to `sanitize_key` fixes silent camelCase lowercasing in the meta bag safe projection (`childCount`, `rowIndex`, `unlocksAt` now round-trip correctly). `ControlRegistry::collectValidRecords()` runs `flattenParentChildOrder($sorted)` DFS pass — children emit immediately after parent; orphaned children (parent absent from current pass) fall back to root position. `ControlCenterListController` bumps `viewModelVersion` 2→3 to signal the `parentPublicId` schema addition. Drawer state (`brand-control-center-app.js`) gains `state.expandedRows` (persisted via `localStorage['dbvc.ve.control-center.expanded-rows']`, deviations-from-default) + `state.searchAutoExpandedRows` (transient, populated at every render from Notion-pattern ancestor walk). `filteredItems` refactored to two-pass tree-aware filter (parents short-circuit past status/priority; leaves hidden when parent collapsed; parents with 0 visible children drop away). `renderRow` renders parent rows with a leading `<button class="__row-disclosure">` (rotating chevron via `.is-expanded` + i18n aria-label + `data-dbvc-ve-control-center-action="toggle-tree-row"`) and a `.__row-childcount` chip in the action cell in place of Open. Leaf rows get `is-child` class + `aria-level=2` + standard indent via CSS (`padding-left: 44px` + faint hairline connector at 24px via `background: linear-gradient`). New `handleTreeKeydown` root listener: ArrowRight expands collapsed parent, ArrowLeft collapses expanded parent, ArrowUp/Down move focus between visible rows. `createTableWrap` gives the `<table>` `role="tree"` + `aria-label`. New CSS selectors + 4 new i18n keys (`controlCenterTreeExpand/Collapse/ChildCountOne/ChildCountMany`). Panel contract byte-identical: leaf Open still mounts the existing editor panel with the same single-subfield descriptor and the same `shared_field` mutation contract.

**R5.7-c — Release notes + real-browser QA plan (2026-09-02, this section).** Release notes updated; QA plan documented in `qa/R5-7-TREE-BROWSER-QA-REPORT.md` (structured as an executable checklist for the maintainer to run at 1440×900 + 1280×720 against the live LocalWP site).

## Feature gates & isolation (verified) — R5.7

- **Two flags, default-off (unchanged from R3-D).** The R5.7 tree UI is only available when both the Visual Editor master flag AND the Brand Control Center flag are on. The tree metaphor activates only when a provider emits `meta.role='repeater_parent'` + `parentPublicId` on child records — every existing flat record renders identically to pre-R5.7.
- **Row-signature integrity guard.** `AbstractAcfResolver::verifyExpectedRowSignature` re-computes the row's current signature at save time and rejects the write with `concurrent_reorder_detected` on mismatch. Verified by `VisualEditorControlCenterR57ATest::test_signature_is_deterministic_across_calls` + `test_signature_is_sensitive_to_value_changes` + `test_signature_strips_acf_row_transient_keys`. Legacy descriptors without a signature bypass the check (backwards-compat).
- **Cross-provider parent link rejected.** A child record whose `parentPublicId` starts with a different provider prefix is silently dropped from the field — the record still surfaces flat rather than being hidden. Verified by `VisualEditorControlRegistryTest::test_r57b_cross_provider_parent_public_id_is_dropped`.
- **Orphaned child falls back to root.** A child whose parent was filtered out (or never registered) surfaces as a top-level orphan rather than disappearing entirely. Verified by `VisualEditorControlRegistryTest::test_r57b_orphaned_child_falls_back_to_root_position`.
- **Panel contract byte-identical.** Leaf Open in the tree fires the same `dbvc:visual-editor:absorb-descriptor` event with the same publicId payload the flat drawer does. R4-D-1 save-status-strip works uniformly because leaves emit tokens the drawer's `activeToken` tracker already handles. No panel-side code changed for R5.7.
- **ARIA tree semantics.** Table has `role="tree"` + `aria-label`; parents get `role="treeitem" aria-level="1" aria-expanded`; leaves get `role="treeitem" aria-level="2"`. Verified by `visual-editor-brand-control-center-state.test.cjs::R5.7-b: table gains ARIA role=tree` + related tests.
- **`viewModelVersion` bumped 2→3.** Signals the `parentPublicId` schema addition on `items[]`; downstream consumers can gate on the version to distinguish pre-R5.7-b from post-. Verified by `VisualEditorControlCenterR4ATest` + `VisualEditorControlCenterRoutesTest` assertion updates.

## Side effects & boundaries — R5.7

- **Writes:** none from R5.7-b (UI-only); R5.7-a's save path routes through the existing `MutationService` pipeline via `AbstractAcfResolver::writeRepeaterSubfieldValue` (which already existed pre-R5.7 for post-context repeaters). The new addition is the signature-guard hook + repeater-subfield descriptor factory. No new REST routes.
- **Storage:** `localStorage['dbvc.ve.control-center.expanded-rows']` per viewer, deviations-from-default rule (empty when everything is collapsed as default). No server-side persistence for tree expansion state — it's a per-viewer UI preference.
- **Frontend enqueue footprint:** unchanged bundle count (drawer CSS + JS grew by ~150 lines each; no new files). No new bootstrap keys beyond the 4 new i18n strings.
- **Meta bag key casing.** `sanitizeMetaKey` is case-preserving. This is a behavior change from `sanitize_key`'s silent lowercasing — camelCase keys emitted pre-R5.7-b were being lowercased (`unlocksAt` → `unlocksat`) so any pre-existing consumer reading `item.meta.unlocksAt` was getting `undefined`. Post-R5.7-b they read the intended camelCase key. If a downstream consumer was compensating by reading the lowercased form, they need to read the original casing now.

## Rollback runbook — R5.7

R5.7 rollback is feature-level, non-destructive, and staged so a UI-only revert can preserve the save-side infrastructure.

1. **UI-only rollback (fastest, non-destructive).** Revert only R5.7-b commits — the drawer's tree-render additions in `brand-control-center-app.js` + `control-center.css` + the 4 new AssetLoader i18n keys + the `ControlRecord::$parentPublicId` field + `sanitizeMetaKey` + `ControlRegistry::flattenParentChildOrder` + `viewModelVersion` bump. Effect: the drawer reverts to R5.7-a's flat interim UI (N+1 records per curated repeater — one muted parent + N available leaves), which is fully functional Option-A UX. Save path stays intact (row-signature integrity preserved). Frontend consumers reading the new `parentPublicId` field see `undefined` and their tree-render code paths short-circuit.
2. **Full R5.7 rollback (revert R5.7-a + R5.7-b together).** Revert the DBVC descriptor factory + resolver signature guard + Vertical `maybeExpandRepeaterRecord` + all of R5.7-b. Effect: the `settings_nav_menus > menus > menu_posts` record returns to R5.6's `unsupported` state (correctly muted, no Open button) — the same state it was in before R5.7 shipped. No data changes; the maintainer's live-site menus repeater is untouched.
3. **The R3 two-part kill switch still gates the whole surface.** Disabling either flag closes the entire Brand Control Center (drawer + REST routes + toolbar entry) — same behavior as pre-R5.7. Rolling back R5.7 while the kill switch is on leaves the R3 popover + drawer functional; rolling back the kill switch also closes R5.7.
4. **No content is orphaned.** R5.7 writes nothing itself — every save flows through the existing `MutationService` pipeline via `AbstractAcfResolver::writeRepeaterSubfieldValue`. Whatever the maintainer saved via a repeater-leaf Open call is ordinary ACF row data that the standard `update_field($parent_repeater_key, $rows, 'option')` path would have written from ACF admin. ## Feature gates & isolation (verified) — R5.later-a

- **Two flags, default-off (unchanged from R3-D).** Palette grouping activates only when both the Visual Editor master flag AND the Brand Control Center flag are on.
- **Curator opt-in.** Palette grouping fires only when the curator sets `palette_group_key` on ≥ 2 sibling color_picker records via CurationStore. Missing key → no palette parent, records surface flat as pre-R5.later-a. Solo opt-in (count=1) → no palette parent (the `>= 2` guard prevents "a palette of one" disclosure for no gain).
- **Color-picker-only in MVP.** `countPaletteMembers` gates on `field_type === 'color_picker'` — non-color records carrying the key contribute nothing to the count and stay flat. Verified by PHPUnit `test_non_color_picker_with_palette_key_is_ignored`.
- **Read-only.** Individual color save routes through the unchanged R5.2+color_picker → AcfColorPickerResolver → writeGroupedFieldValue path. Palette grouping is a discovery + drawer-render layer only; no new REST endpoints, no new mutation authority, no new mutation contracts.
- **R5.7-b tree UI shared surface.** Palette parents render via the same disclosure + count chip + ARIA + keyboard nav + localStorage persistence + search-auto-expand code paths repeater parents use. Verified by both the widened jsdom test and by live behavior (item 6, 13 in the QA report).
- **Coexistence with R5.7-a repeater expansion.** Palette grouping runs AFTER the R5.7-a repeater-expansion block in `getControls()`. If a record is a repeater-nested subfield, the repeater path fires first and `continue`s past palette grouping; palette grouping only fires on records the repeater path didn't consume. The shared `$parents_emitted` dedup map handles both parent types.
- **Panel contract byte-identical for leaves.** Leaf Open in a palette tree fires the same `dbvc:visual-editor:absorb-descriptor` event with the same publicId payload flat records use.
